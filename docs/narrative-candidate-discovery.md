# 每日叙事整理的材料候选

每日 Scout 保留原来的关键词候选，并补充两路有界候选，再由同一个 Scout LLM 阅读摘录、判断叙事关系。检索命中不直接归卷；不增加 Jev 或第二个初筛 LLM。

公开版仍需在设置中显式开启“夜间自动整理叙事卷”，并配置叙事选材模型。未开启时不读取这批候选、不产生新的语义请求。语义路径读取用户当前已准备好的 embedding 模型及对应索引；模型未准备好时退回其他路径。

- **关键词**：沿用原有提取、排序和配置。默认每个起始材料最多 12 个，配置最大 24 个；这些候选不会因新增路径被挤掉。
- **已有实体**：读取 `current_entities`，要求实体抽取的内容/证据版本仍有效。使用已验证名字，不把 `alias_suggestions` 当已确认身份。共享实体或正文出现这些名字可产生候选，最多额外 4 个。日记尚无实体抽取，但可按这些名字匹配正文。
- **语义**：使用现有 EmbeddingClient 的 query instruction、模型及索引 profile；不换模型、不重建向量。读取现有 Event/Scene 整篇和 passage 索引，最多额外 4 个。先限制当前合法材料 ID，再取结果，保留 Search 的可读性和内容版本校验。日记不在现有向量索引中。

合并时按材料类型＋ID 去重，并保留 `candidate_sources`、每路排名及命中实体/关键词。最多 32 个候选；默认最多 20 个。命中理由按起始材料与候选这一对保存，原文缓存只缓存正文摘录与 fingerprint。

实体和关键词仍遵守原有未归卷、可读、active 及 covered Event 排除规则。本改动没有把已归卷材料加入只读背景，也没有改材料归属校验。共享名字不证明同一实体；语义相似不证明同一条叙事。最终决定仍由原模型与现有写入校验负责。

## 请求与失败

语义 query 使用标题及最多 4,000 字符的材料检索文本。沿用现有主题选材的 0.3 cosine 候选下限；这是候选阈值，不是归卷置信度或已校准的叙事关系阈值。最多处理当前 prompt 会消费的 24 个起始材料，同时最多 3 个语义查询；每次沿用 EmbeddingClient 的 20 秒超时、无新增重试。

无语义配置时仍运行关键词＋实体路径。模型/索引 profile 不符、服务失败、索引暂不可用时保留其他路径；扫描回执 `candidate_search` 记录语义状态、失败次数及各路候选对数量，不记录私人正文或上游异常内容。部分或全部语义失败不推进成功输入指纹，下一轮允许重试。新实体标注、索引变化及候选预算/配置变化会使旧扫描指纹失效。

## 回退

在现有 `background.germany_config_file` 指定的 YAML 中设置：

```yaml
narrative_rolls:
  hybrid_candidates_enabled: false
```

默认开启补充候选；关闭后使用原关键词路径，无新增语义调用。不修改已有材料关系、正文或索引 profile。

## 验证

`tests/test_narrative_candidates.py` 使用临时数据库及 mock provider，覆盖实体独立召回、日记匹配、过期实体拒绝、ASCII 名字边界、去重及来源、关键词候选保留、语义名单过滤、过期索引拒绝、异常回退、恢复重试、新标注触发重扫及关闭开关。

这是实现和本地测试说明，不代表已经部署或线上召回质量已验证。
