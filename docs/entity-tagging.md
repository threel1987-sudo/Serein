# 打标时提取实体

主域建议与实体分别校验：主域缺失、类型错误或不在当前目录中时保留原主域，仍保存有可靠出处的实体；无效 JSON 和缺失／错误的实体数组将该次任务标为失败，不自动重复付费请求。正文或绑定材料变化时会生成新的任务；未变化的失败项由页面显式重试。

公开版在同一次“打标”模型请求里返回主域和实体，不新增实体专用模型或另一轮请求。设置 → 模型 → 打标选模型后，后台每十五秒检查一次持久变化队列，每批至多处理两条活动 Event / Scene；空队列不扫描全部记忆，也不调用模型。新建、正文修订、活动来源绑定变化或生命周期变化才会重新入队；升级后会一次性补查已有活动 Event / Scene。没有配置模型时等待。已有主域、标题、正文、cues 保持不变，只给未分类且尚未打标的记忆补主域。以前已经完成主域打标的记忆会补提实体；已经有当前提取结果的记忆不会反复调用模型。

实体包括明确命名的人物、地点、组织、作品、项目和产品等，不提取情绪、主题、代词和泛称。每个实体必须带材料 ID，以及包含完整名字的连续引用。程序核对材料属于当前记忆、引用逐字存在、名字在引用中，并记录字符位置；无出处或引用错误的候选被丢弃，数量记录到 `entity_rejected_count`。缺少实体数组属于格式错误，可重试；合法的空数组表示这次没有找到实体。失败最多尝试三次，不把格式错误伪装成提取成功。

有绑定原话时，从当前有效原话核对，出处类型为 `bound_source`；没有绑定原话时允许核对记忆正文，明确标记 `memory_body`，不能把正文说成聊天原话。单次材料上限 24,000 字符，记忆概要输入上限 16,000 字符；截断会留下 `entity_materials_truncated`，不表示完整扫描过超长材料。实体最多保存 20 个，每个最多八处引用。相同名字只做 Unicode/大小写规范化去重；模型给的别名只有在引用里也出现时才保存为建议，绝不据此合并身份。

结果保存在记忆修订的 `tagged_entities` 元数据里，并投影到可重建的实体索引；主域和实体使用同一次事务保存。提取结果绑定标题、正文、活动来源快照的指纹。请求期间发生编辑或来源解绑，旧结果不会写入；请求之后发生这些变化，旧结果立即不再用于实体候选。后台为变化后的内容重新提取。已归档或删除的文档不提取，召回仍遵守已有的可浮现、领域排除和冷却规则。

Operit 导入仍尊重“自动打标”选项；关闭此选项的导入不自动补实体。文件完整导入之后才发起打标。升级前的旧导入任务如果正文已经变过，沿用跳过规则，不覆盖人工编辑。

这里只保存实体及其出处和记忆归属，不生成实体关系或共同出现边。实体匹配只提供候选，不能替代正文证据直接注入。开启联想后，最多辅助一条关联记忆进入候选池，仍需走现有筛选；打标本身不创建关系。

Event 落库后的可选 Arc Linker 不消费这些实体结果。它直接用 Event 标题和正文检索已有 Arc 卡，再独立判断是否归属；因此打标失败不会阻断 Arc 归档。
